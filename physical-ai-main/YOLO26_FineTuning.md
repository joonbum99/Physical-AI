# YOLO26n 기반 선박 작업구역 검출 모델 파인튜닝 보고서

## 1. 프로젝트 개요

### 1.1 모델 학습 목적

본 프로젝트의 목적은 선박 내부 이미지에서 로봇이 작업해야 하는 영역을 자동으로 검출하는 것이다. 좌표 변환이나 회전각도 추정이 아니라, 다음 3개 작업 대상을 이미지에서 구분하고 바운딩박스로 검출하는 기능을 중심으로 한다.

| Class ID | 검출 클래스 | 검출 대상 |
|---:|---|---|
| 0 | 볼트 체결부 | 로봇이 볼팅 작업을 수행해야 하는 체결 위치 |
| 1 | 용접부 | 배관·철판 연결부 등 용접이 필요한 위치 |
| 2 | 케이블 접속부 | 커넥터·단자 등 케이블 체결이 필요한 위치 |

학습 모델은 `yolo26n.pt`를 사용한다. COCO 사전학습 가중치를 기반으로 선박 작업 이미지에 전이학습을 수행하며, 3개 클래스에 맞춰 최종 분류 레이어가 자동으로 재구성된다.

---

## 2. 학습 전략

### 2.1 전이학습 적용

```python
model = YOLO("yolo26n.pt")
```

처음부터 모델을 학습하는 Scratch 방식보다, 사전학습된 `yolo26n.pt`를 사용하는 전이학습 방식을 적용한다.

사전학습 모델은 이미 선, 모서리, 질감, 윤곽과 같은 시각적 특징을 학습한 상태이므로 볼트, 용접선, 케이블 커넥터처럼 형태가 뚜렷한 산업 객체를 더 빠르게 학습할 수 있다. 또한 학습 이미지가 많지 않더라도 초기 수렴 속도가 빠르고 과적합 위험을 줄일 수 있다.

---

### 2.2 2단계 파인튜닝

선박 내부 작업 이미지는 COCO 데이터와 배경, 조명, 금속 질감 및 촬영 환경이 다르므로 다음과 같이 2단계로 학습한다.

#### Stage 1: Backbone 일부 동결

```text
freeze=10
```

초기 30 Epoch 동안 Backbone 앞부분을 동결하고, 새롭게 구성된 검출 Head와 상위 특징 레이어를 우선 학습한다.

- 사전학습 특징이 초기에 급격히 손상되는 것을 방지한다.
- 3개 작업 클래스에 대한 분류 기준을 먼저 안정화한다.
- 작은 산업 데이터셋에서 초기 Gradient 불안정을 줄인다.

#### Stage 2: 전체 레이어 해제

```text
freeze=None
lr0=0.001
```

Stage 1에서 생성된 최적 가중치를 불러온 뒤 전체 레이어를 해제하고 270 Epoch를 추가 학습한다.

- 일반 객체 중심의 COCO 특징을 선박 내부의 금속 표면과 작업부 특징으로 수정한다.
- 볼트 체결부, 용접부, 케이블 접속부의 세부적인 질감 차이를 학습한다.
- 낮은 학습률을 적용하여 기존에 학습된 특징이 급격히 무너지는 것을 방지한다.

총 학습 상한은 300 Epoch이며, 실제 학습은 `patience`에 따라 그보다 먼저 종료될 수 있다.

## 4. 파라미터 선정 근거

### 4.1 `model="yolo26n.pt"`

YOLO26 Nano 모델을 사용한다.

#### 학습 측면

- 모델 크기가 작아 Google Colab 환경에서도 빠르게 반복 학습할 수 있다.
- 파라미터 수가 적어 소규모 산업 이미지에서 과적합 위험이 상대적으로 낮다.
- 사전학습 가중치를 그대로 사용하므로 클래스 수가 3개로 바뀌어도 Backbone 특징은 유지된다.

#### 성능 측면

- 선박 내부 카메라 및 산업용 PC에서 실시간 검출에 유리하다.
- 볼트, 용접부, 케이블 접속부처럼 형태가 비교적 명확한 객체를 검출하기에 충분한 기본 성능을 제공한다.
- 향후 정확도가 부족할 경우 동일한 조건으로 `s`, `m` 모델과 비교할 수 있지만, 초기 시스템은 속도가 빠른 `n` 모델이 적합하다.

---

### 4.2 `imgsz=1280`

선박 내부 전체 사진에서 작업 부분은 이미지의 일부만 차지할 가능성이 높으므로 입력 해상도를 1280으로 설정한다.

#### 학습 측면

- 이미지 축소 과정에서 작은 볼트와 케이블 커넥터의 특징이 사라지는 것을 줄인다.
- 용접선과 금속 경계처럼 얇은 형상 정보를 더 많이 보존한다.

#### 성능 측면

- 멀리 촬영된 볼트 체결부와 작은 접속부의 미검출을 줄일 수 있다.
- 640 해상도보다 작은 객체의 바운딩박스 위치를 정밀하게 학습할 수 있다.

해상도가 증가하면 VRAM 사용량과 학습시간도 증가하므로 배치는 8로 제한한다.

---

### 4.3 `batch=8`

1280 해상도에서는 이미지 한 장이 차지하는 GPU 메모리가 커지므로 배치 크기를 8로 설정한다.

#### 학습 측면

- Google Colab의 제한된 VRAM에서 OOM 오류가 발생할 가능성을 낮춘다.
- 너무 작은 배치보다 Gradient가 안정적이며, 한 번에 여러 작업 환경을 비교해 학습할 수 있다.

#### 성능 측면

- 배치 크기는 정확도를 직접 높이는 파라미터라기보다 GPU 활용률과 학습 안정성에 영향을 준다.
- VRAM이 충분하더라도 무리하게 배치를 높이기보다 해상도 1280을 유지하는 것이 작은 작업부 검출에 더 중요하다.

OOM 오류가 발생하면 `batch=4`로 낮추고, VRAM이 충분하면 `batch=16`을 비교한다.

---

### 4.4 `epochs=300`

전체 학습 상한을 300 Epoch로 설정한다.

#### 학습 측면

- 사전학습 모델은 Scratch 학습보다 빠르게 수렴하므로 무조건 많은 Epoch가 필요하지 않다.
- 다만 선박 내부는 COCO와 도메인 차이가 크기 때문에 전체 레이어를 충분히 미세조정할 시간이 필요하다.
- 300 Epoch는 학습 기회를 충분히 제공하고, 실제 종료 시점은 `patience`가 결정한다.

#### 성능 측면

- 볼트와 케이블처럼 일부 형태가 유사한 객체를 구분하려면 초기 수렴 이후에도 세부 특징 학습이 필요하다.
- Epoch를 무조건 늘리는 것보다 검증 성능이 최고인 `best.pt`를 사용하는 것이 중요하다.

---

### 4.5 `patience=20`

검증 성능이 20 Epoch 동안 향상되지 않으면 학습을 자동 종료한다.

#### 학습 측면

- 설명서에서 기본 `patience=100`은 대부분의 학습에서 지나치게 길 수 있다고 제시한다.
- 최고 성능 이후 불필요하게 학습을 지속하는 것을 방지한다.
- 시간과 Colab GPU 사용량을 줄인다.

#### 성능 측면

- 검증 성능이 하락하는 구간까지 계속 학습하는 과적합을 줄인다.
- 일시적인 성능 변동을 고려하여 즉시 종료하지 않고 20 Epoch의 여유를 둔다.

---

### 4.6 `cache="disk"`

학습 이미지를 디스크 캐시에 저장한다.

#### 학습 측면

- 매 Epoch마다 원본 파일을 반복해서 읽는 대기시간을 줄인다.
- `cache=True`의 RAM 캐시보다 속도는 느리지만, 고해상도 이미지가 많을 때 Colab RAM이 부족해지는 위험이 낮다.
- 첫 Epoch 이후 이미지 로딩 병목을 줄여 GPU 대기시간을 감소시킨다.

#### 성능 측면

- 캐시는 모델 정확도를 직접 높이지 않는다.
- 데이터 로딩을 안정화하여 전체 학습시간을 단축하는 역할을 한다.

데이터가 작고 Colab RAM이 충분하면 `cache=True`를 사용할 수 있다.

---

### 4.7 `amp=True`

16비트와 32비트 연산을 함께 사용하는 AMP를 활성화한다.

#### 학습 측면

- GPU VRAM 사용량을 줄인다.
- 한 Epoch의 학습시간을 단축한다.
- 가중치를 실제로 업데이트해야 하는 중요 연산은 필요한 정밀도로 처리한다.

#### 성능 측면

- 설명서 기준으로 최종 정확도 차이는 거의 없다.
- 해상도 1280을 안정적으로 사용하기 위해 반드시 활성화하는 것이 유리하다.

AMP를 비활성화하면 학습이 느려지고 VRAM 사용량이 증가하지만 정확도 향상은 거의 기대하기 어렵다.

---

### 4.8 `fraction=1.0`

최종 학습에서는 전체 이미지 데이터를 사용한다.

#### 학습 측면

- `fraction=0.10`은 데이터 경로, 라벨 오류 및 코드 실행 여부를 빠르게 확인하는 용도로만 사용한다.
- 최종 모델에서 일부 데이터만 사용하면 조명, 배경 및 작업 형상 다양성이 감소한다.

#### 성능 측면

- 볼트 체결부, 용접부, 케이블 접속부의 다양한 촬영 조건을 모두 학습해야 현장 일반화 성능이 향상된다.
- `fraction`으로 얻은 성능은 최적 파라미터 판단 근거로 사용하지 않는다.

권장 사용 순서는 다음과 같다.

```text
1차 실행 확인: fraction=0.10
최종 모델 학습: fraction=1.0
```

---

### 4.9 `scale=0.5`

객체 크기가 변하는 증강 범위를 적용한다.

#### 학습 측면

- 카메라와 작업 대상 사이의 거리에 따라 작업부가 크게 또는 작게 촬영되는 상황을 학습한다.
- 같은 볼트와 용접부가 이미지 내에서 서로 다른 크기로 나타나도 동일 클래스로 인식하도록 한다.

#### 성능 측면

- 근거리와 원거리 작업부에 대한 검출 성능을 동시에 확보할 수 있다.
- 지나치게 작은 객체가 생성되면 라벨 특징이 사라질 수 있으므로 기본 수준인 0.5를 사용한다.

---

### 4.10 `mosaic=0.5`

Mosaic 증강은 중간 강도인 0.5로 적용한다.

#### 학습 측면

- 서로 다른 이미지의 작업부와 배경을 조합하여 데이터 다양성을 높인다.
- 한 이미지 안에서 크기와 위치가 다른 작업 대상을 동시에 학습할 수 있다.
- `mosaic=1.0`은 실제 선박 내부와 다른 비현실적인 장면이 지나치게 많이 생성될 수 있다.

#### 성능 측면

- 이미지 수가 부족한 상황에서 작업부의 위치와 배경 다양성을 보완한다.
- 선박 배관과 금속 구조물의 실제 문맥도 중요하므로 과도한 Mosaic은 피한다.

따라서 증강을 완전히 제거하는 0.0과 항상 적용하는 1.0 사이의 0.5를 선정한다.

---

### 4.11 `multi_scale=False`

가변 입력 해상도 학습은 사용하지 않는다.

#### 학습 측면

- `scale`은 이미지 안의 객체 크기를 변화시키고, `multi_scale`은 전체 입력 프레임의 크기를 변화시킨다.
- 산업용 카메라 입력은 실제 운영 시 고정된 해상도로 사용할 가능성이 높다.
- 입력 해상도를 1280으로 고정하면 배치별 VRAM 변동과 학습시간 변동을 줄일 수 있다.

#### 성능 측면

- 고정된 카메라와 작업거리에서 입력 조건을 일관되게 유지할 수 있다.
- 작은 작업부의 픽셀 정보가 배치마다 달라지는 것을 방지한다.

다양한 해상도의 카메라를 동시에 사용하지 않는다면 `multi_scale`은 필요하지 않다.

---

### 4.12 `optimizer="AdamW"`

최적화 알고리즘은 AdamW로 설정한다.

#### 학습 측면

- 설명서에서는 소규모 데이터와 낮은 총 반복 횟수에서 AdamW가 빠르게 수렴하는 특성이 있다고 제시한다.
- 3개 클래스의 특수 산업 데이터에 전이학습을 수행하므로 초기 적응 속도가 중요하다.
- 최적화 알고리즘을 수동으로 고정하면 실험 간 조건을 동일하게 유지할 수 있다.

#### 성능 측면

- 선박 이미지처럼 COCO와 차이가 있는 데이터에서 사전학습 가중치를 안정적으로 미세조정할 수 있다.
- 클래스별 이미지 수가 많지 않은 초기 프로젝트에서 빠르게 기준 성능을 확보하기 적합하다.

향후 데이터가 크게 증가하고 총 Iteration이 10,000회를 크게 초과하면 `optimizer="auto"`와 비교한다.

---

### 4.13 `lr0=0.001`

초기 학습률은 0.001로 설정한다.

#### 학습 측면

- 2단계에서 전체 레이어를 해제할 때 높은 학습률을 적용하면 기존 사전학습 특징이 급격히 변경될 수 있다.
- 설명서의 2단계 파인튜닝 예시와 같이 낮은 학습률로 전체 모델을 미세조정한다.
- AdamW를 직접 지정하므로 `lr0`가 그대로 적용된다.

#### 성능 측면

- 선박 내부 특징을 학습하면서도 기존의 형태 및 윤곽 검출 능력을 유지한다.
- 학습 진동과 검증 성능 급락을 줄인다.

---

### 4.14 `lrf=0.10`

학습 마지막 단계의 학습률을 초기 학습률의 10% 수준으로 감소시킨다.

#### 학습 측면

- 초기에는 비교적 빠르게 선박 데이터에 적응하고, 후반부에는 작은 학습률로 가중치를 세밀하게 조정한다.
- 마지막까지 동일한 학습률을 유지해 최적점을 지나치는 현상을 줄인다.

#### 성능 측면

- 클래스 간 경계가 유사한 작업부의 미세 특징을 안정적으로 학습한다.
- 학습 후반의 검증 손실 변동을 줄이는 데 목적이 있다.

---

### 4.15 `warmup_epochs=3`

초기 3 Epoch 동안 학습률을 단계적으로 증가시킨다.

#### 학습 측면

- 파인튜닝 시작 직후 큰 Gradient가 사전학습 가중치를 흔드는 것을 방지한다.
- 새롭게 구성된 3개 클래스 Head가 안정적으로 학습을 시작하도록 한다.
- 전체 300 Epoch 중 초기 구간만 적용하여 실제 학습시간 손실을 최소화한다.

#### 성능 측면

- 초기 Loss 급등과 비정상적인 학습 발산 가능성을 줄인다.
- 초기화된 검출 Head와 기존 Backbone 사이의 학습 균형을 확보한다.

---

### 4.16 `freeze=10 → freeze=None`

동결 범위는 2단계로 변경한다.

| 단계 | 설정 | 목적 |
|---|---:|---|
| Stage 1 | `freeze=10` | 초기 Backbone 특징을 보호하고 새 클래스 Head를 우선 학습 |
| Stage 2 | `freeze=None` | 선박 내부 질감과 작업부 형상에 맞춰 전체 모델 수정 |

#### 학습 측면

단일 단계에서 처음부터 전체 레이어를 학습하면 Head는 아직 작업 클래스를 이해하지 못한 상태에서 Backbone까지 함께 변경될 수 있다. 1단계에서 Head를 먼저 안정화한 뒤 전체 레이어를 해제하면 학습이 더 안정적이다.

#### 성능 측면

Backbone을 계속 동결하면 COCO 특징에만 의존하여 금속 반사, 용접 비드 및 케이블 단자의 특수한 패턴을 충분히 학습하지 못한다. 따라서 최종 모델은 반드시 전체 레이어를 해제해 학습한다.

---

### 4.17 `conf`

`conf`는 학습 파라미터가 아니라 학습된 모델의 결과를 표시하는 추론 임계값이다.

#### 오류 분석 설정

```text
conf=0.10
```

신뢰도가 낮은 후보까지 모두 확인하여 다음 문제를 찾는다.

- 금속 반사를 용접부로 오검출하는 사례
- 일반 볼트와 실제 작업 대상 볼트를 혼동하는 사례
- 케이블이나 배관을 접속부로 잘못 인식하는 사례
- 실제 작업부를 낮은 신뢰도로만 검출하는 사례

#### 현장 운영 설정

```text
conf=0.50
```

실제 로봇 작업 판단에는 신뢰도가 낮은 결과를 제외해야 하므로 초기 운영값을 0.50으로 설정한다.

임계값을 너무 낮추면 오검출이 증가하고, 너무 높이면 실제 작업부를 놓칠 수 있다. 최종 값은 검증데이터의 Precision과 Recall을 비교해 조정한다.

---

### 4.18 `cls_pw=0.40`

클래스 간 데이터 불균형이 확인될 경우 적용한다.

#### 적용 조건

다음과 같이 특정 클래스의 학습 이미지가 현저히 적을 때 사용한다.

```text
볼트 체결부 이미지 수 > 용접부 이미지 수 > 케이블 접속부 이미지 수
```

#### 학습 측면

- 이미지가 적은 클래스의 분류 손실이 학습 과정에서 무시되는 것을 줄인다.
- 다수 클래스에만 모델이 편향되는 현상을 완화한다.

#### 성능 측면

- 희소 클래스의 AP와 Recall을 높이는 데 목적이 있다.
- 전체 mAP가 상승하더라도 특정 클래스 성능이 하락할 수 있으므로 클래스별 AP를 확인해야 한다.

클래스별 라벨 수가 비슷하다면 `cls_pw`를 임의로 조정하지 않는다. 데이터가 부족한 클래스는 가중치 조정보다 실제 이미지를 추가하는 것이 우선이다.

## 6. 학습 전 빠른 오류 점검

전체 데이터를 장시간 학습하기 전에 `fraction=0.10`으로 일부 데이터만 사용하여 다음 항목을 점검한다.

```python
model.train(
    data=data_yaml,
    fraction=0.10,
    epochs=3,
    imgsz=1280,
    batch=8
)
```

점검 대상은 다음과 같다.

1. `data.yaml`의 Train 및 Validation 경로가 정상인지 확인한다.
2. 볼트 체결부, 용접부, 케이블 접속부의 클래스 번호가 올바른지 확인한다.
3. 이미지와 라벨 파일의 이름이 일치하는지 확인한다.
4. 배치 이미지에서 바운딩박스가 작업 대상에 정확히 표시되는지 확인한다.
5. GPU VRAM 부족 오류가 발생하지 않는지 확인한다.

`fraction` 학습 결과는 최종 성능 평가에 사용하지 않고 설정 오류를 찾는 용도로만 사용한다.

## 7. 성능 평가 기준

본 프로젝트는 전체 mAP만으로 모델을 평가하지 않고 각 작업 클래스의 성능을 개별적으로 확인해야 한다.

| 평가항목 | 확인 목적 |
|---|---|
| 전체 mAP | 전체 작업구역 검출 성능 확인 |
| 클래스별 AP | 특정 클래스만 성능이 낮은 문제 확인 |
| Precision | 일반 배관·금속 구조물의 오검출 여부 확인 |
| Recall | 실제 작업부를 놓치는 미검출 여부 확인 |
| Confusion Matrix | 용접부·케이블 접속부 간 혼동 확인 |
| 추론 결과 이미지 | 바운딩박스 위치와 클래스 표시 직접 확인 |

로봇 작업에서는 잘못된 위치를 작업 대상으로 판단하는 오검출뿐 아니라 실제 작업 위치를 찾지 못하는 미검출도 치명적이다. 따라서 전체 mAP가 높더라도 세 클래스 중 하나의 Recall이 낮으면 모델을 현장에 적용해서는 안 된다.

## 8. 주요 트러블슈팅

| 문제 현상 | 우선 점검 파라미터 | 조치 |
|---|---|---|
| 작은 볼트 체결부 미검출 | `imgsz`, `batch` | `imgsz=1280` 유지, OOM 발생 시 배치만 축소 |
| 학습시간이 지나치게 김 | `cache`, `amp` | `cache="disk"`, `amp=True` 적용 |
| Colab RAM 부족 | `cache` | `cache=True` 대신 `"disk"` 사용 |
| GPU VRAM 부족 | `batch`, `imgsz` | 배치를 8에서 4로 낮추고 해상도는 우선 유지 |
| 검증 성능이 조기에 정체 | `patience`, `lr0` | `patience=20` 유지, Stage 2 학습률 확인 |
| 학습 성능만 높고 검증 성능 하락 | `epochs`, `patience`, `mosaic` | 조기 종료 모델 사용, Mosaic 과다 적용 여부 확인 |
| 작업부 크기 변화에 약함 | `scale` | `scale=0.5` 적용 여부 확인 |
| 비현실적인 합성 이미지가 많음 | `mosaic` | `mosaic=0.5`에서 0.0으로 낮춰 비교 |
| 희소 클래스 성능 저하 | `cls_pw` | 클래스 수량 확인 후 `cls_pw=0.40` 조건부 적용 |
| 결과가 너무 적게 표시됨 | `conf` | 오류 분석 시 `conf=0.10`으로 낮춰 확인 |
| 오검출이 과도하게 많음 | `conf` | 운영 임계값을 0.50 이상으로 조정 |
| 전이학습 후 성능이 정체됨 | `freeze` | Stage 2에서 `freeze=None` 적용 여부 확인 |

## 9. 최종 결론

본 프로젝트의 최종 권장 학습 구성은 다음과 같다.

```text
YOLO26n 사전학습 모델
        ↓
1280 고해상도 입력
        ↓
Stage 1: freeze=10으로 검출 Head 우선 학습
        ↓
Stage 2: freeze=None으로 전체 레이어 미세조정
        ↓
볼트 체결부·용접부·케이블 접속부 검출
        ↓
클래스별 AP·Precision·Recall 검증
```

핵심 파라미터는 다음과 같다.

```text
model=yolo26n.pt
imgsz=1280
batch=8
epochs=300
patience=20
cache="disk"
amp=True
fraction=1.0
scale=0.5
mosaic=0.5
multi_scale=False
optimizer="AdamW"
lr0=0.001
lrf=0.10
warmup_epochs=3
freeze=10 → None
conf=0.10 → 0.50
cls_pw=0.40 조건부 적용
```

본 모델의 성능을 결정하는 가장 중요한 요소는 단순히 Epoch를 늘리는 것이 아니라, 실제 로봇이 작업해야 하는 볼트 체결부·용접부·케이블 접속부를 일관된 기준으로 라벨링하고 각 클래스별 검증 성능을 확인하는 것이다.

최종 모델은 마지막 Epoch의 `last.pt`가 아니라 검증 성능이 가장 높았던 `best.pt`를 사용한다.
